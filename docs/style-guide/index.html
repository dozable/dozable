Dozable · the dashboard (doz ui)

Style guide — a living specimen

Every sample on this page is drawn by the dashboard’s real stylesheet, Sources/DozableWeb/WebSource/app.css, loaded in place, with the icons the dashboard vendors and the marks of its icon registry. The markup is what the components in Sources/DozableWeb/WebSource/app/ produce. Light and dark sit side by side — color-scheme is the theme, exactly as in the app.

A change to the dashboard’s look updates this page in the same commit. A sample here that no longer matches the app is a bug in this page.

Rules every piece of the dashboard keeps

  1. Tokens only. Every colour, size, radius, shadow and layer is a var(--…) from app.css :root, with light-dark(); no literal colour anywhere else.
  2. 13 px is the UI size (--fs-md); 14 for prose in wizards and section titles; 16 for a step’s title; 20 for a page or modal title.
  3. One button family — default, .primary, .quiet, .danger, .sm/.lg, .icon-only (with aria-label). One primary per view: the verb that moves forward (Next, Create, Start).
  4. One notice surface: the callout (info · ok · warn · bad). A failure is said where the action started and stays; a toast is only for success.
  5. Never colour alone: a pill is glyph + word; a dimmed option says why in readable text (--ink-2, never --ink-3).
  6. Wizards are the modal (.wiz-modal › .wm-box): wizHead (title, ✕, the step strip), a scrolling .w-body, a footer that never leaves the screen. Quick try is the same modal made full-page (.wiz-modal.full) with a labelled Close.
  7. Choices are cards (.wiz-choice, .base-card, Quick try’s .qt-item): chosen = a ring; a segmented control for 2–4 short modes.
  8. Icons are the vendored Lucide set only (listed at the end). A new icon is a vendoring change (VENDOR.json). Marks (agents, vendors) come from the icon registry, monochrome, in currentColor.
  9. Commands and files are shown exactly, monospace, copyable, never holding a secret; a long file folds away behind a disclosure.
  10. Light and dark both work, and the theme is the app’s switch (data-theme on <html>; auto follows macOS). Text is set with textContent, never markup.
